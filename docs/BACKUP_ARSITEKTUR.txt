  * Item produk sudah ada & locked -> ditolak

  * order_number: {tgl_kirim_YYYYMMDD}_{tgl_pesan_YYYYMMDD}_{HHMM}_{NamaReseller}
    contoh: 20261028_20261026_1337_2Ratu1RajaBuYeni
  * Kalau order_number tabrakan -> suffix -02, -03
  * customer_ref_no: KK22-ORD-NNNN

17. UPDATE FASE 4.4 - ADMIN LOCK & TOGGLE
================================================================
File baru:
  AdminPesanan.gs -> handleLockItemPesanan_, handleUnlockItemPesanan_,
                     handleToggleProdukAktif_, updateHeaderStatusByRekap_

Endpoint API baru:
  [DONE] lockItemPesanan    -> Lock 1-N item per PO (LockService 30s)
  [DONE] unlockItemPesanan  -> Unlock 1 item + wajib isi alasan (audit)
  [DONE] toggleProdukAktif  -> Soft lock produk (PO existing tetap)

Status header otomatis:
  * Ada item pending + locked -> status = partial_locked
  * Semua locked, tidak ada pending -> status = locked
  * Semua pending -> status = submitted
  * DONT touch status shipped/done/cancelled

Lock behavior:
  * Lock 1 atau banyak item sekaligus
  * Skip item yang sudah locked (dengan alasan)
  * LockService mencegah race condition 2 admin lock bareng

Toggle produk behavior (Opsi B - approved):
  * Produk nonaktif -> hilang dari katalog reseller
  * PO existing dengan produk ini TIDAK terpengaruh
  * Admin/owner tetap lihat semua produk termasuk nonaktif
  * Hitung pending_items_affected untuk info ke admin
