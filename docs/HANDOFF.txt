6. ATURAN BISNIS
================================================================
PRODUK & RESELLER:
- nama_produk UNIQUE (kunci Mekari)
- nama_reseller UNIQUE (DisplayName Mekari)
- Filter migrate: ProductCategory='Barang Jadi', Type='customer'
- Soft lock produk = aktif=FALSE (PO existing tetap jalan)
- Admin/owner LIHAT produk nonaktif, reseller TIDAK
- Struktur Mekari JANGAN DIUBAH (tambahan selalu di kanan)

PESANAN - AUTO-MERGE:
- 1 reseller max 1 PO AKTIF per tgl_kirim
- Kalau ada PO existing same tgl_kirim -> merge:
  * Produk baru                -> tambah baris (pending)
  * Produk sudah ada & pending -> qty digabung
  * Produk sudah ada & locked  -> TOLAK item itu (WA admin)
- Kalau tgl_kirim beda -> buat PO baru
- Reseller tidak bisa hapus item locked (WA admin)

ORDER NUMBER FORMAT:
- {YYYYMMDD_kirim}_{YYYYMMDD_pesan}_{HHMM}_{NamaReseller}
- Contoh: 20261028_20261026_1337_2Ratu1RajaBuYeni
- Tabrakan -> suffix -02, -03
- Normalisasi: hapus spasi+non-alphanumeric, max 25 char, preserve case
- customer_ref_no: KK22-ORD-NNNN (internal)
- id_pesanan: KK22-PSN-NNNN (PK)

STATUS ITEM  : pending -> locked -> shipped -> done
STATUS HEADER:
- submitted      : semua pending
- partial_locked : mix pending+locked
- locked         : semua locked
- shipped        : sudah dikirim
- done           : selesai
- cancelled      : dibatalkan
- JANGAN touch status shipped/done/cancelled saat rekap

  - best_for_customer: coba semua kombinasi, pilih termurah

FLOW ORDER DENGAN PROGRAM:
  1. Reseller pilih program di pesan.html (checkbox visible program)
     atau auto-apply kalau target + visibility=auto_apply
  2. Preview harga setelah apply (di UI)
  3. Submit → backend hitung final price via rule engine
  4. Snapshot harga program ke kolom PESANAN.program_snapshot (audit)
  5. Kalau program mode_approval=manual → status=pending_approval
  6. Admin approve → status=submitted (bisa di-lock)
     Admin reject → status=rejected + alasan
  7. Kalau mode_approval=auto → langsung submitted

APPROVAL DI LEVEL ITEM (Q5=C):
  - Kalau PO punya mix item program (perlu approval) + item normal
  - Item program = pending_approval, item normal = submitted
  - Admin bisa:
    * Approve seluruh PO (approve semua pending)
    * Approve per item (partial)

  - Backend handle per-item approval_status

EXPIRED PROGRAM (Q6=A):
